# Шаблоны технической документации

Шаблоны лежат рядом с этим файлом в папке `templates/`:

| Артефакт | Шаблон | Папка / файл назначения | Имя файла |
|---|---|---|---|
| Технические соглашения (один на проект) | `templates/conventions.md` | `docs/tech/` | `conventions.md` |
| Технический дизайн фичи | `templates/tech-design.md` | `docs/tech/designs/` | `TDD-NNN-<slug>.md` |
| Задача для Dev | `templates/task.md` | `docs/tech/tasks/` | `TASK-NNN-<slug>.md` |
| Архитектурное / технологическое решение | `.kilo/skills/analysis-templates/templates/adr.md` | `docs/analysis/decisions/` | `ADR-NNN-<slug>.md` |

## Правила

1. Прочитай нужный шаблон (`.kilo/skills/tech-templates/templates/<file>`).
2. Определи следующий свободный номер `NNN` по файлам в папке назначения (glob `TDD-*.md`, `TASK-*.md`, `ADR-*.md`). Нумерация TASK сквозная по всему проекту.
3. `<slug>` — короткое имя в kebab-case на латинице (например, `clipboard-writer`).
4. Заполни **все** разделы. Неприменимый раздел помечай «Н/П — <почему>», а не удаляй: исполнитель должен видеть, что раздел рассмотрен.
5. Подсказки в шаблоне (текст в `<угловых скобках>` и строки-пояснения, начинающиеся с `>`) замени содержимым и удали.
6. `conventions.md` существует в единственном экземпляре: если он уже есть — обновляй его, а не создавай заново. Каждое изменение отражай в его «Журнале изменений».
7. Задача должна быть самодостаточной: исполнитель читает только TASK и `conventions.md`. Всё остальное, что ему нужно (выдержки из REQ/US/TDD, контракты соседних модулей), копируй в задачу.
8. После создания обнови индекс `docs/tech/README.md` (таблицы «Технические дизайны», «Задачи», раздел «Порядок выполнения»). Для ADR — таблицу ADR в `docs/analysis/README.md`.
9. Статусы:
   - TDD: `Draft` → `Review` → `Approved` → `Implemented` / `Superseded`;
   - TASK: `Draft` → `Ready` → `In Progress` → `Review` → `Done`, а также `Blocked`.
   Задача получает `Ready`, только если все её зависимости описаны, а открытых вопросов, влияющих на неё, нет.
