Подготовь техническую документацию для реализации в проекте fast-cow-screenshot:

$ARGUMENTS

Если аргументы — `CLR-NNN`, обработай этот запрос уточнения от Dev по разделу «Запросы уточнения от Dev (CLR)» своих инструкций.
Если аргументы не указаны — сначала обработай все CLR со статусом `Open` и адресатом `Tech` из @docs/tech/README.md, затем возьми все требования и user stories со статусом `Review` или `Approved` из @docs/analysis/README.md, по которым ещё нет TDD.

Действуй по своему рабочему процессу:
1. Изучи входные артефакты Analyst (REQ, US, RES, ADR), `docs/tech/README.md`, `docs/tech/conventions.md`, открытые CLR и текущее состояние кода и сборки.
2. Составь список нужных технических решений. По каждому нерешённому вопросу задай пользователю вопрос с вариантами (рекомендуемый — первым) и зафиксируй ответ в ADR.
3. Загрузи skill `tech-templates`. Создай или обнови `docs/tech/conventions.md`, затем напиши TDD.
4. Разбей TDD на задачи TASK для Dev, заполнив все разделы шаблона с максимальной детализацией: исполнитель — более слабая модель, и каждая неясность для неё — остановка работы и запрос уточнения.
5. Пройди чек-лист самопроверки по каждой задаче.
6. Обнови `docs/tech/README.md` и, если создавались ADR, — `docs/analysis/README.md`.
7. Кратко перечисли созданные файлы, принятые решения, ответы на CLR, порядок выполнения задач, допущения и открытые вопросы.
