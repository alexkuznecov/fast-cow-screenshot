# ADR-003: Хранение настроек (JSON в %APPDATA%), логирование (SLF4J + Logback), тесты (JUnit 6 + MockK)

| Поле | Значение |
|---|---|
| Статус | Accepted |
| Дата | 2026-10-18 |
| Автор | Tech |
| Связанные | REQ-001 (.4, .45, .53, .55, §7), RES-001 §6 |

## Контекст

Настройки должны сохраняться между запусками: директория по умолчанию, последняя папка «Сохранить как», горячие
клавиши, флажок указателя, флажок автосохранения. Нужны логи для диагностики и тестовый стек.

## Рассмотренные варианты

- Настройки: JSON-файл (kotlinx.serialization) / `.properties` / `java.util.prefs` (реестр).
- Логи: SLF4J + Logback / `java.util.logging`.
- Тесты: JUnit 6 + MockK + kotlin-test / Kotest.

## Решение (выбор пользователя от 2026-10-18)

- Настройки — `%APPDATA%\fast-cow-screenshot\settings.json`, `kotlinx-serialization-json` 1.11.0. Запись атомарная
  (временный файл + `ATOMIC_MOVE`). Если файл повреждён, применяются значения по умолчанию.
- Логи — `slf4j-api` 2.0.17 + `logback-classic` 1.5.38. Файл `%LOCALAPPDATA%\fast-cow-screenshot\logs\app.log`,
  ежедневная ротация, 14 файлов.
- Тесты — JUnit Jupiter 6.1.3 (BOM), MockK 1.14.11, `kotlin-test` 2.4.21.

## Последствия

- **Положительные:** настройки читаемы и легко сбрасываются удалением файла; стандартные инструменты.
- **Отрицательные:** плагин компилятора serialization; JUnit 6 требует явного `junit-platform-launcher` в Gradle 9.
