# ADR-001: Платформа и стек: Kotlin/JVM 2.4, JDK 25, Gradle 9, Compose Multiplatform Desktop

| Поле | Значение |
|---|---|
| Статус | Accepted |
| Дата | 2026-10-18 |
| Автор | Tech |
| Связанные | REQ-001 (§7, N6, N8), RES-001 (§2, §3a, рекомендация 3) |

## Контекст

REQ-001 §7 требует выбрать UI-фреймворк для десктопного JVM-приложения на Kotlin. Нужны: значок в трее, оверлей
выделения на каждом мониторе с отрисовкой 1:1 к физическим пикселям, всплывающее окно уведомления без фокуса,
небольшое окно настроек. В простое RSS должен быть ≤ 200 МБ (REQ-001.N6). Пользователь хочет JDK 25 LTS и дальнейшие
обновления JDK.

Сначала пользователь предложил TornadoFX. Последний релиз TornadoFX — `no.tornado:tornadofx:1.7.20` (январь 2020).
Он собран под Kotlin 1.3 и Java 8 и больше не развивается. Это прямой риск для «обновления на новые версии JDK».
Пользователь согласился заменить его на Compose Multiplatform.

## Рассмотренные варианты

1. **Compose Multiplatform Desktop 1.12.2** — декларативный UI от JetBrains поверх AWT/Skia.
2. **Swing + FlatLaf 3.7.2** — входит в JDK, самый лёгкий.
3. **JavaFX 25 без TornadoFX** — нативные диалоги файлов, но отдельный UI-поток рядом с AWT (трей всё равно AWT).
4. **TornadoFX 1.7.20 + JavaFX 25** — проект заброшен.

## Сравнение

| Критерий | Compose | Swing + FlatLaf | JavaFX 25 | TornadoFX |
|---|---|---|---|---|
| Совместимость с будущими JDK | Высокая (активная разработка) | Максимальная | Высокая | Низкая |
| Память (N6) | +60–100 МБ (Skia) после первого окна — нужен замер | Минимальная | Средняя | Средняя |
| Удобство UI-кода | Высокое | Низкое | Среднее | Среднее |
| Интеграция с AWT (трей, HWND для JNA) | Прямая (Compose построен на AWT) | Прямая | Через мост | Через мост |
| Упаковка | Встроенный jpackage (`createDistributable`) | Вручную | Вручную | Вручную |

## Решение

- Язык: **Kotlin 2.4.21** (Kotlin/JVM). Сборка: **Gradle 9.8.1** (Kotlin DSL, wrapper, version catalog).
- JDK: **Temurin 25 LTS** (`jvmToolchain(25)`).
- UI: **Compose Multiplatform 1.12.2**, библиотека компонентов **Material (M2) 1.12.2**. Material3 для CMP 1.12 есть
  только в alpha, поэтому не используется.
- Где Compose не используется (обоснование — точность и скорость):
  - **Оверлей выделения области** — Swing `JFrame` + Java2D. Кадр рисуется напрямую из `BufferedImage` без копий
    (REQ-001.N3, N6), в пикселях устройства (1:1, REQ-001.19/20).
  - **Трей** — AWT `SystemTray`/`PopupMenu`. Compose `Tray` требует `application {}` и собственного жизненного цикла.
  - **Диалоги файлов и папок, подтверждение перезаписи** — нативные диалоги Windows через JNA (см. ADR-002):
    у Compose нет своих диалогов, а AWT `FileDialog` на Windows не умеет одновременно задавать фильтр `PNG (*.png)`
    и предзаполненное имя.
- Упаковка: Compose Gradle plugin, задача `createDistributable` (jpackage app-image со встроенным runtime).

## Последствия

- **Положительные:** современный стек на поддерживаемых версиях; готовая упаковка; прямой доступ к HWND окон
  для WinAPI.
- **Отрицательные / риски:**
  - Skia увеличивает RSS — замер N6 в TASK-016.
  - Два стиля UI-кода (Compose и Swing для оверлея) — границы закреплены в `docs/tech/conventions.md`.
  - JNA и Skiko на JDK 24+ выдают предупреждения о native access — снимаются флагом `--enable-native-access=ALL-UNNAMED`.
