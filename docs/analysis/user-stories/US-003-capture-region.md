# US-003: Захват произвольной области, в том числе через границу мониторов

| Поле | Значение |
|---|---|
| Статус | Review |
| Приоритет | Must |
| Оценка | L |
| Требования | REQ-001.1, REQ-001.2, REQ-001.5, REQ-001.13–REQ-001.21, REQ-001.52, REQ-001.53, REQ-001.56, REQ-001.N3, REQ-001.N5 |

## История

**Как** пользователь,
**я хочу** выделить мышью произвольную прямоугольную область экрана, в том числе захватывающую несколько мониторов,
**чтобы** получить снимок только нужного фрагмента без последующей обрезки.

## Критерии приёмки

### AC-1: Замороженный кадр
- **Given** на экране открыто выпадающее меню другого приложения
- **When** пользователь нажимает `Ctrl+Shift+3` (горячая клавиша «Область» по умолчанию)
- **Then** не позднее чем через 250 мс на всех мониторах появляется оверлей с неподвижным кадром экрана, выпадающее меню видно на кадре

### AC-2: Выделение и захват
- **Given** оверлей выделения отображается
- **When** пользователь зажимает левую кнопку мыши, протягивает прямоугольник и отпускает кнопку
- **Then** оверлей закрывается сразу, без шага подтверждения и правки; снимок содержит ровно выделенную область замороженного кадра в физических пикселях

### AC-3: Выделение через границу мониторов с разным масштабом
- **Given** монитор A с масштабом 100 % и монитор B с масштабом 150 % расположены рядом
- **When** пользователь выделяет область, которая начинается на A и заканчивается на B
- **Then** снимок содержит обе части без разрывов и масштабирования, размер равен сумме физических размеров частей

### AC-4: Отображение размера
- **Given** пользователь протягивает выделение
- **When** выделение меняется
- **Then** рядом с выделением показывается размер в физических пикселях в формате `Ш×В`

### AC-5: Отмена
- **Given** оверлей выделения отображается (выделение начато или нет)
- **When** пользователь нажимает Esc или правую кнопку мыши
- **Then** оверлей закрывается, буфер обмена не меняется, файл не создаётся

### AC-6: Клик без перетаскивания
- **Given** оверлей выделения отображается
- **When** пользователь делает одиночный клик (выделение меньше 2×2 px)
- **Then** ситуация обрабатывается как отмена (AC-5)

### AC-7: Оверлей не попадает в снимок
- **Given** пользователь завершил выделение
- **When** снимок сформирован
- **Then** на снимке нет элементов оверлея (затемнения, рамки, подписи размера, перекрестия)

### AC-8: Указатель мыши при включённой настройке
- **Given** включена настройка «Включать указатель мыши в снимок», в момент нажатия `Ctrl+Shift+3` указатель находился в точке P
- **When** пользователь выделяет область, которая содержит точку P
- **Then** на снимке нарисован указатель в той форме и позиции, что были в момент нажатия клавиши; если выделение не содержит P — указателя на снимке нет

## Граничные случаи

- Выделение в обратном направлении (снизу-справа вверх-влево).
- Выделение заходит в пустую зону виртуального стола — эта часть заливается серым `#808080` (REQ-001.11).
- Монитор отключили, пока открыт оверлей — оверлей закрывается без падения приложения.
- Повторное нажатие горячих клавиш при открытом оверлее игнорируется (REQ-001.5).
- Выделение на всю площадь всех мониторов.
- Нажатие Shift или стрелок во время выделения ни на что не влияет (REQ-001.56, Won't в v1).

## Заметки / UI

- Вне выделения кадр затемняется (например, на 40 %), выделенная область показывается без затемнения.
- Курсор в оверлее — перекрестие.
- Модификаторы (Shift — квадрат, стрелки — подгонка) и правка выделения после отпускания в v1 не делаются (REQ-001.56).
- **Допущение:** одно окно оверлея на каждый монитор, а не одно окно на весь виртуальный стол (см. RES-001).
