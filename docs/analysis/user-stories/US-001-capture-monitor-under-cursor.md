# US-001: Захват монитора под курсором

| Поле | Значение |
|---|---|
| Статус | Review |
| Приоритет | Must |
| Оценка | M |
| Требования | REQ-001.1–REQ-001.3, REQ-001.5–REQ-001.8, REQ-001.20–REQ-001.22, REQ-001.52, REQ-001.53, REQ-001.N1, REQ-001.N5 |

## История

**Как** пользователь с несколькими мониторами,
**я хочу** одной горячей клавишей снять тот монитор, на котором сейчас курсор,
**чтобы** быстро получить снимок нужного экрана без лишних частей с соседних мониторов.

## Критерии приёмки

### AC-1: Захват монитора, на котором находится курсор
- **Given** подключены два монитора, приложение работает в фоне, курсор на втором (не основном) мониторе
- **When** пользователь нажимает `Ctrl+Shift+1` (горячая клавиша «Монитор под курсором» по умолчанию)
- **Then** создаётся снимок только второго монитора, размер изображения равен физическому разрешению второго монитора

### AC-2: Физическое разрешение при HiDPI
- **Given** монитор 3840×2160 с масштабом 150 % в параметрах Windows
- **When** пользователь делает захват монитора под курсором
- **Then** изображение имеет размер 3840×2160 (а не 2560×1440), эталонный узор совпадает пиксель в пиксель

### AC-3: Работа без фокуса
- **Given** приложение свёрнуто в трей, фокус в другом приложении (например, браузере)
- **When** пользователь нажимает горячую клавишу
- **Then** захват выполняется, фокус остаётся в исходном приложении

### AC-4: Конфликт горячей клавиши
- **Given** комбинация клавиш режима уже занята другим приложением
- **When** приложение запускается
- **Then** показывается уведомление с названием занятой комбинации, остальные режимы захвата работают

### AC-5: Повторное нажатие во время захвата
- **Given** выполняется захват
- **When** пользователь повторно нажимает горячую клавишу до завершения захвата
- **Then** повторное нажатие игнорируется, создаётся ровно один снимок

### AC-6: Собственные окна не попадают в снимок
- **Given** на экране отображается уведомление приложения о предыдущем снимке
- **When** пользователь делает новый захват
- **Then** на новом снимке уведомления приложения нет

### AC-7: Указатель мыши по умолчанию не попадает в снимок
- **Given** настройка «Включать указатель мыши в снимок» выключена (значение по умолчанию)
- **When** пользователь делает захват монитора под курсором
- **Then** на снимке нет указателя мыши

### AC-8: Указатель мыши включён настройкой
- **Given** пользователь включил настройку «Включать указатель мыши в снимок»
- **When** пользователь делает захват; указатель в этот момент имеет форму стрелки, его горячая точка — в физических координатах (500, 300) монитора
- **Then** на снимке нарисована стрелка, её горячая точка — в (500, 300); после перезапуска приложения настройка остаётся включённой

## Граничные случаи

- Курсор на границе двух мониторов — выбор по правилу Windows `MonitorFromPoint`.
- Положение курсора нельзя определить — захватывается основной монитор (REQ-001.8).
- Монитор с отрицательными координатами (расположен слева от основного).
- Портретная ориентация монитора.

## Заметки / UI

- Горячая клавиша по умолчанию — `Ctrl+Shift+1` (REQ-001.52), переназначается в настройках (REQ-001.4).
- Флажок «Включать указатель мыши в снимок» — в окне настроек, действует для всех режимов (REQ-001.53).
- Результат захвата передаётся в буфер обмена (US-004) и на автосохранение (US-005).
