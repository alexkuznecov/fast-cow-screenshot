# US-005: Автосохранение снимка в директорию по умолчанию

| Поле | Значение |
|---|---|
| Статус | Review |
| Приоритет | Must |
| Оценка | M |
| Требования | REQ-001.27–REQ-001.35, REQ-001.49, REQ-001.54, REQ-001.N4, REQ-001.N12 |

## История

**Как** пользователь,
**я хочу**, чтобы каждый снимок автоматически сохранялся PNG-файлом в известную мне папку,
**чтобы** потом найти его, даже если буфер обмена уже перезаписан.

## Критерии приёмки

### AC-1: Автосохранение с именем по шаблону
- **Given** директория по умолчанию — `C:\Users\Александр\Pictures\Screenshots`, локальное время 2026-10-18 20:00:48
- **When** пользователь делает захват
- **Then** в директории появляется файл `Screenshot_2026-10-18_20-00-48.png`, это корректный PNG с размером снимка

### AC-2: Коллизия имён
- **Given** в директории уже есть `Screenshot_2026-10-18_20-00-48.png`
- **When** пользователь делает ещё один захват в ту же секунду
- **Then** новый файл сохраняется как `Screenshot_2026-10-18_20-00-48_1.png`, существующий файл не меняется

### AC-3: Директории нет
- **Given** директория по умолчанию задана, но удалена с диска
- **When** пользователь делает захват
- **Then** директория создаётся вместе с промежуточными папками, файл сохраняется

### AC-4: Запись невозможна
- **Given** директория по умолчанию на отключённом USB-диске
- **When** пользователь делает захват
- **Then** показывается уведомление с причиной ошибки и кнопкой «Сохранить как…» (скрывается через 3 с); снимок есть в буфере обмена и доступен как последний снимок, «Сохранить как…» остаётся доступным в меню трея

### AC-5: Неблокирующее сохранение
- **Given** снимок 4K сохраняется на диск
- **When** пользователь сразу делает следующий захват
- **Then** следующий захват выполняется без ожидания окончания записи, оба файла сохраняются корректно

### AC-6: Уведомление об успехе
- **Given** снимок `Screenshot_2026-10-18_20-00-48.png` успешно сохранён в `C:\Users\Александр\Pictures\Screenshots`
- **When** появляется уведомление
- **Then** в нём указаны имя файла `Screenshot_2026-10-18_20-00-48.png` и папка `C:\Users\Александр\Pictures\Screenshots`; через 3 с уведомление скрывается само; клик по уведомлению до скрытия открывает Проводник с выделенным файлом

### AC-7: Серия снимков
- **Given** показано уведомление о снимке 1
- **When** пользователь делает снимок 2 раньше, чем прошли 3 с
- **Then** уведомление о снимке 1 заменяется уведомлением о снимке 2, отсчёт 3 с начинается заново; уведомления не накладываются друг на друга

### AC-8: Нет повреждённых файлов
- **Given** во время записи файла закончилось место на диске
- **When** запись прерывается
- **Then** в директории нет файла с итоговым именем, содержащего неполный PNG; пользователь получает уведомление об ошибке

## Граничные случаи

- Путь с кириллицей и пробелами (REQ-001.49).
- Папка «Изображения» перенаправлена в OneDrive, синхронизация приостановлена.
- Сетевая директория (UNC) с задержкой ответа — запись в фоне не блокирует UI.
- Перевод часов на летнее/зимнее время — возможна коллизия имён, обрабатывается по AC-2.

## Заметки / UI

- Опциональное отключение автосохранения — REQ-001.35 (Could).
- Уведомление — собственное всплывающее окно приложения в правом нижнем углу основного монитора, а не системный toast: длительность toast-уведомлений задаёт Windows (см. REQ-001 §7, RES-001).
- Макет уведомления: заголовок «Снимок сохранён», строка с именем файла, строка с путём к папке (длинный путь сокращается многоточием в середине), кнопка «Сохранить как…».
- Если путь длинный и сокращён, полный путь показывается во всплывающей подсказке.
