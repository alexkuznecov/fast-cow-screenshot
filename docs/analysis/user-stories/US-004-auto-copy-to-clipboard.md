# US-004: Автоматическое копирование снимка в буфер обмена

| Поле | Значение |
|---|---|
| Статус | Review |
| Приоритет | Must |
| Оценка | S |
| Требования | REQ-001.23–REQ-001.26, REQ-001.58, REQ-001.N1, REQ-001.N2 |

## История

**Как** пользователь,
**я хочу**, чтобы снимок сразу оказывался в буфере обмена,
**чтобы** вставить его в мессенджер или документ через Ctrl+V без дополнительных действий.

## Критерии приёмки

### AC-1: Вставка в популярные приложения
- **Given** выполнен захват в любом режиме
- **When** пользователь нажимает Ctrl+V в Paint, Microsoft Word, Telegram Desktop и Chrome/Edge (поле, принимающее изображения)
- **Then** во всех этих приложениях вставляется изображение, идентичное снимку по размеру и содержимому

### AC-2: Независимость от сохранения
- **Given** директория по умолчанию недоступна для записи
- **When** пользователь делает захват
- **Then** изображение всё равно помещается в буфер обмена, а об ошибке сохранения показывается отдельное уведомление

### AC-3: Буфер занят другим процессом
- **Given** буфер обмена временно заблокирован другим процессом
- **When** пользователь делает захват
- **Then** система повторяет попытку (не менее 5 раз в течение не более 1 с); если буфер освободился — изображение копируется; если нет — показывается уведомление «Не удалось скопировать в буфер обмена», файл сохраняется

### AC-4: Сохранение после выхода
- **Given** снимок скопирован в буфер обмена
- **When** пользователь закрывает приложение через «Выход» в трее
- **Then** изображение можно вставить через Ctrl+V в Paint

### AC-5: Отмена не затрагивает буфер
- **Given** в буфере обмена лежит текст
- **When** пользователь открывает режим «Область» и отменяет его клавишей Esc
- **Then** в буфере обмена остаётся прежний текст

## Граничные случаи

- Очень большое изображение (11520×2160) — вставка работает, время копирования в пределах REQ-001.N2.
- Включена история буфера обмена Windows (Win+V) или синхронизация буфера — снимок попадает туда как обычное содержимое буфера. Это ожидаемое поведение, приложение снимок не исключает (REQ-001.58).
- Пользователь в сеансе RDP с перенаправлением буфера обмена — **Допущение:** в v1 не тестируется.

## Заметки / UI

- Прозрачность в буфере не сохраняется (ограничение формата CF_DIB) — поэтому пустые зоны заливаются непрозрачным серым `#808080`.
